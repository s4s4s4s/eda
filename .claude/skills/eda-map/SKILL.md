# eda — карта

React 19 + TypeScript + Vite 7, PWA (`vite-plugin-pwa`, `registerType: 'prompt'` — новая
версия скачивается сама, но подменяет экран только по нажатию человека). Открыть телефон,
за пять секунд увидеть текущий приём, что в нём лежит и что досыпать, и одним нажатием
записать его в дневник. Живёт на `s4s4s4s.github.io/eda`, деплой — GitHub Actions
(`.github/workflows/deploy.yml`, ветка `main`).

## Главное правило проекта

**Меню и КБЖУ — данные, а не код.** Хардкод меню в исходниках запрещён. Числа берутся
из одного заявленного источника (USDA FoodData Central, SR Legacy 2018-04) и у каждого
продукта записан `fdcId`. **Отсутствие нутриента в датасете — это не ноль:** поля просто
нет, а сумма несёт свою полноту (`known`/`total`), чтобы «неизвестно» никогда не читалось
как «измеренный ноль».

## Данные — `data/`

| Файл | Что внутри |
|---|---|
| `products.yaml` | справочник продуктов, 59 позиций: `per100g`, `micro100g` (все ключи `NUTRIENT_KEYS`), `tags`, меры `pieceG`/`tbspG` с полем `*Source`. Собирается скриптом, правится редко |
| `menu.yaml` | `cycleDays` + список **редакций** (`editions`): каждая редакция — одна порция меню от диетолога, `{ from?, title, days }`; позиции несут граммовку и флаг `where: container \| packet`, шаги сборки, у каждого блюда — устойчивый `id` (слаг). Присланная редакция не переписывает прежнюю — старая неделя остаётся в файле. Первая редакция без `from` обязана описывать весь цикл; остальные обязаны иметь `from`, идти по возрастанию даты и вправе описывать подмножество дней. **Это файл Александра — он правит его руками** |
| `norms.yaml` | суточные нормы нутриентов: источник DRI (Food and Nutrition Board), группа «мужчины 19–30»; часть ключей нормы намеренно не имеет — каротиноиды, ретинол, ЭПК и ДГК, сахара, насыщенные и полиненасыщенные жиры, холестерин; шапка файла объясняет по каждому, почему |

В браузер оба попадают через `?raw`-импорты (`src/data/load.ts`) — приложение работает
офлайн, сети не требует. Тот же файл читает через `node:fs` проверка меню.

## Ядро — `src/core/` (чистое, без React, DOM и localStorage)

| Файл | Ответственность |
|---|---|
| `types.ts` | **контракт всего проекта**: слоты, `Kbju`, `Product`, `Meal` (с устойчивым `id`), `Menu` и `MenuEdition`, `MealLogEntry` (с `mealId`), `Settings`, `Preferences`, `IngredientStance`, `DishRating`, `AppState`, `Violation`; `NUTRIENT_KEYS`, `NUTRIENT_UNIT`/`NUTRIENT_TITLE`/`NUTRIENT_GROUP` и порядок разделов `NUTRIENT_GROUP_ORDER`, `NutrientTotal` со счётчиком полноты, `NutrientNorm`/`NutrientNorms` |
| `data.ts` | разбор YAML в типы: строгая проверка, ссылка на несуществующий продукт — ошибка, а не пропуск; `parseMenu`/`parseEdition` держат инварианты редакций (первая без `from` описывает весь цикл, остальные — по возрастанию `from`) |
| `menu.ts` | **единственное место, где живёт правило выбора редакции**: `menuDayFor(menu, date, cycleDayNum)` берёт самую свежую из действующих на дату редакций, которая описывает нужный день; `mealFor`, `allMeals` (по одному блюду на id, версия из самой свежей редакции, вместе со всеми местами `{ day, slot }`, где оно стоит — для книги предпочтений). Экраны и проверка меню ходят через эти функции, а не перебирают `editions` сами |
| `nutrition.ts` | счёт КБЖУ и нутриентов позиции/приёма/дня; `emptyNutrientTotals`, `addNutrientTotals`, `scaleNutrientTotals`, `incompleteNutrients` |
| `rules.ts` | **`LIMITS` — единственное место, где живут нормы** (порции по тегам, коридор дня 3050–3350, минимум приёма, ягоды, `flaxG`/`chiaG`/`dayOilG` — нормы льна, чиа и масла в граммах, не в ложках); `checkMenu`/`checkEdition` — поиск нарушений по каждой редакции отдельно, чтобы день, повторяющийся в двух редакциях, не смешивал их нарушения |
| `norms.ts` | покрытие суточных норм: `nutrientCoverage` сравнивает сумму дня с `data/norms.yaml`, у каждой строки — `CoverageState` (`ok`/`no-norm`/`not-comparable`/`no-data`), ratio не обрезается сверху |
| `week.ts` | недельная сводка дневника: `weekSummary` (средние только по дням, где есть данные), `weekCoverage` — «Итоги недели» по всем позициям `NUTRIENT_KEYS`, норма окна = суточная × число дней с данными |
| `preferences.ts` | книга предпочтений: `setStance`/`stanceOf` (отметки продуктов «люблю»/«не ем»), `rateDish`/`ratingOf`/`clearRating` (оценка блюда 1–10 и комментарий), `mealStances` |
| `verdict.ts` | плюсы и минусы приёма (`mealVerdict`): плюс — нутриент ≥ 30 % суточной нормы (не больше пяти) либо ингредиент «люблю»; минус — «не ем», превышение верхнего предела, натрий выше CDRR, больше половины состава без данных |
| `cycle.ts` | день цикла (1..8) из даты старта и ручного сдвига, день партии (1..4), текущий приём по времени суток, `todayLocal`, `formatDateFull` (день недели и число из `WEEKDAY_NAMES`/`MONTH_NAMES_GENITIVE`, без `Intl` — ядро остаётся чистым) |
| `log.ts` | дневник: `logMeal` (снапшот КБЖУ и нутриентов — правка меню задним числом прошлое не переписывает), `unlogMeal`, `dayTotal`, `dayNutrientTotals`, `clearLog`, `logFootprint` |

## Выгрузка — `src/core/export/`

Каналы за общим интерфейсом. **Требование контракта: кнопка не имеет права делать вид,
что отправила.** Канал либо работает, либо честно объясняет причину недоступности; канал,
который не может подтвердить доставку сам, возвращает `pending`.

| Файл | Ответственность |
|---|---|
| `types.ts` | `ExportPayload` (`kind: 'meal' \| 'day'`), `Availability`, `ExportResult`, `ExportChannel`. **Соглашение: снапшот приёма полный, долю применяет потребитель** |
| `format.ts` | тексты для буфера, `buildDayCsv` (39 колонок), `CSV_HEADER`, `csvNutrientCell` (пустая ячейка = нет данных, `0` = честный ноль) |
| `health-shortcut.ts` | мост в Apple Health через «Команды»: `buildShortcutUrl` с `x-callback-url`, `healthNutrients` (нутриент без данных не отправляется вовсе) |
| `csv.ts` | канал CSV: системный шаринг файла, при его отсутствии — текст для копирования |
| `clipboard.ts` | канал буфера обмена — работает всегда, запасной путь |
| `index.ts` | `buildChannels`, `sendViaChannel`, `readCallback` |

| `RatingEditor.tsx` | общий примитив оценки блюда — шкала 1–10 сеткой 5×2 и поле комментария; используется и на главном экране, и в шторке «Книга» |

**Внешний вид описан в `DESIGN.md` в корне репозитория** — это источник правды, а не
«как было»: цвета обеих тем, шкала типографики, радиусы, движение, зоны нажатия и
обязательный порядок блоков главного экрана. Цвет и размер по месту не задаются, только
токеном из `theme.css`. Границы трёх CSS-файлов разведены намеренно, чтобы правки
не сталкивались; отдельного `export.css` нет — шторка выгрузки живёт в общей теме.

`src/state/storage.ts` (—) — единственный, кто знает про localStorage. Ключ
`eda.state.v1`, версия формата `CURRENT_VERSION` (сейчас 3 — в состоянии появился раздел
`preferences`, книга предпочтений). `deserialize` **никогда не бросает**:
битый день выпадает, дневник выживает. `saveState` возвращает `SaveResult` — провал
записи не глотается, экран показывает причину.

## Скрипты — `scripts/`

| Файл | Что делает |
|---|---|
| `build-products.mjs` | собирает `products.yaml` из офлайн-выгрузки USDA SR Legacy; `npm run products` |
| `check-menu.ts` | **проверка меню до закупки поваром**; `npm run check-menu` |
| `make-icons.mjs` | иконки PWA и 12 стартовых экранов iOS из одного силуэта-миски; `npm run icons` |

**Два уровня строгости проверки меню.** Без флага (локально, гейт перед закупкой) любое
нарушение даёт `exit 1`. С `--warn-only` (в выкатке) сломанный файл меню по-прежнему
валит сборку, а не сошедшееся питание печатается предупреждением: меню на восемьдесят
калорий легче нормы — не повод оставлять человека без приложения.

Отчёт печатает каждую редакцию отдельно, своей шапкой («РЕДАКЦИЯ: имя, действует
с датой; дней: N из 8»), и делит нарушения редакции на «Так устроена вся редакция»
(правило сработало больше чем в половине её дней — замысел диетолога, не опечатка,
одна строка со счётчиком и примером) и «Выбивается из редакции — проверить»
(кандидаты в опечатку, поимённо); печатает `printViolations`.

## Тесты — `test/`

Обычные `.ts`, собираются esbuild и гоняются node-ом; `npm test` — вся цепочка, двенадцать
наборов (см. `scripts` в `package.json`): `data`, `cycle`, `nutrition`, `rules`, `log`,
`export`, `storage`, `norms`, `week`, `preferences`, `verdict`, `menu` (`npm run test:menu`
— разбор редакций и выбор действующего дня, идёт сразу после `test:data`). В выкатке идут
**до** сборки: красный тест оставляет на телефоне прошлую рабочую версию.

## Что важно знать до правок

- Прямого пути из браузера в Apple Health нет и быть не может. Мост — «Команды»,
  и подтверждение приходит только возвратом `x-success` в приложение.
- Записать несколько показателей одним действием «Команд» нельзя — сколько показателей,
  столько действий. Приложение всегда отдаёт весь словарь; сколько ляжет в Health,
  решает команда, а не приложение.
- `satFat`, `monoFat`, `polyFat` в Health не попадают — таких типов образца нет.
  Они остаются в буфере обмена и в CSV.
- Ключей, токенов и паролей в репозитории нет и быть не может: приложению не с чем
  аутентифицироваться, оно ни к какому внешнему сервису не ходит.
