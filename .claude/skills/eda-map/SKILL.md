# eda — карта

React 19 + TypeScript + Vite 7, PWA (`vite-plugin-pwa`, autoUpdate). Открыть телефон,
за пять секунд увидеть текущий приём, что в нём лежит и что досыпать, и одним нажатием
записать его в дневник. Живёт на `s4s4s4s.github.io/eda`, деплой — GitHub Actions
(`.github/workflows/deploy.yml`, ветка `main`).

## Главное правило проекта

**Меню и КБЖУ — данные, а не код.** Хардкод меню в исходниках запрещён. Числа берутся
из одного заявленного источника (USDA FoodData Central, SR Legacy 2018-04) и у каждого
продукта записан `fdcId`. **Отсутствие нутриента в датасете — это не ноль:** поля просто
нет, а сумма несёт свою полноту (`known`/`total`), чтобы «неизвестно» никогда не читалось
как «измеренный ноль».

## Данные — `data/`

| Файл | Размер | Что внутри |
|---|---:|---|
| `products.yaml` | 45 КБ | справочник продуктов: `per100g`, `micro100g` (29 нутриентов), `tags`, меры `pieceG`/`tbspG` с полем `*Source`. Собирается скриптом, правится редко |
| `menu.yaml` | 23 КБ | 8 дней × 4 приёма: позиции с граммовкой и флагом `where: container \| packet`, шаги сборки. **Это файл Александра — он правит его руками** |

В браузер оба попадают через `?raw`-импорты (`src/data/load.ts`) — приложение работает
офлайн, сети не требует. Тот же файл читает через `node:fs` проверка меню.

`src/state/storage.ts` (11 КБ) — единственный, кто знает про localStorage. Ключ
`eda.state.v1`, версия формата `CURRENT_VERSION`. `deserialize` **никогда не бросает**:
битый день выпадает, дневник выживает. `saveState` возвращает `SaveResult` — провал
записи не глотается, экран показывает причину.

## Скрипты — `scripts/`

| Файл | Размер | Что делает |
|---|---:|---|
| `build-products.mjs` | 23 КБ | собирает `products.yaml` из офлайн-выгрузки USDA SR Legacy; `npm run products` |
| `check-menu.ts` | 6,3 КБ | **проверка меню до закупки поваром**; `npm run check-menu` |
| `make-icons.mjs` | 3 КБ | иконки PWA из одного исходника; `npm run icons` |

**Два уровня строгости проверки меню.** Без флага (локально, гейт перед закупкой) любое
нарушение даёт `exit 1`. С `--warn-only` (в выкатке) сломанный файл меню по-прежнему
валит сборку, а не сошедшееся питание печатается предупреждением: меню на восемьдесят
калорий легче нормы — не повод оставлять человека без приложения.

## Тесты — `test/`

Обычные `.ts`, собираются esbuild и гоняются node-ом; `npm test` — вся цепочка.
`data` (22 группы), `nutrition` (11), `rules` (10), `log` (10), `export` (13),
`storage` (5), `cycle` (4). В выкатке идут **до** сборки: красный тест оставляет
на телефоне прошлую рабочую версию.

## Что важно знать до правок

- Прямого пути из браузера в Apple Health нет и быть не может. Мост — «Команды»,
  и подтверждение приходит только возвратом `x-success` в приложение.
- Записать несколько показателей одним действием «Команд» нельзя — сколько показателей,
  столько действий. Приложение всегда отдаёт весь словарь; сколько ляжет в Health,
  решает команда, а не приложение.
- `satFat`, `monoFat`, `polyFat` в Health не попадают — таких типов образца нет.
  Они остаются в буфере обмена и в CSV.
- Ключей, токенов и паролей в репозитории нет и быть не может: приложению не с чем
  аутентифицироваться, оно ни к какому внешнему сервису не ходит.
